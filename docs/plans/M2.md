# M2 — Single-node broker (plan)

SPEC refs: §2.2 (Store abstraction), §3.1 (HW checkpoint), §4.2 (HW/LEO read bounds), §4.4 (epoch
checks), §4.5 (acks; single node), §7.1/7.3/7.4 (API, error codes, partitioner), §8 FR1–FR5, FR9,
FR11 (topics/produce/consume subset), §10 (config). Acceptance (§9): integration test — 100k keyed
records across 6 partitions; consume all; per-key order verified; restart broker and re-read
everything.

Out of scope: Raft store (M5), replication/ISR/purgatory for acks=all with followers (M6),
InitProducer/idempotence (M7), groups (M4), client library (M3; `streamqctl` uses raw gRPC stubs
in M2 and is switched to `pkg/client` in M3), metrics (M8), SIGTERM controlled shutdown (M8; M2 does
a plain graceful stop).

New dependencies (all on the approved list): `google.golang.org/grpc`, `google.golang.org/protobuf`,
`github.com/spf13/cobra`, `gopkg.in/yaml.v3`, `golang.org/x/sync/errgroup`.

## 1. Protobuf API (`api/v1/streamq.proto`, `api/v1/internal.proto`)

Package `streamq.v1`, generated into `gen/v1` (`streamqv1`). Only M2 RPCs are added now; later
milestones add RPCs/messages/fields (non-breaking). Field numbers are never reused.

```proto
enum ErrorCode { ERROR_CODE_NONE = 0; ERROR_CODE_UNKNOWN_TOPIC_OR_PARTITION = 1;
  ERROR_CODE_TOPIC_ALREADY_EXISTS = 2; ERROR_CODE_INVALID_REPLICATION_FACTOR = 3;
  ERROR_CODE_NOT_LEADER = 4; ERROR_CODE_FENCED_LEADER_EPOCH = 5; ERROR_CODE_OFFSET_OUT_OF_RANGE = 6;
  ERROR_CODE_NOT_ENOUGH_REPLICAS = 7; ERROR_CODE_REQUEST_TIMED_OUT = 8; ERROR_CODE_CORRUPT_MESSAGE = 9;
  ERROR_CODE_MESSAGE_TOO_LARGE = 10; ERROR_CODE_OUT_OF_ORDER_SEQUENCE = 11;
  ERROR_CODE_UNKNOWN_PRODUCER_ID = 12; ERROR_CODE_ILLEGAL_GENERATION = 13;
  ERROR_CODE_REBALANCE_IN_PROGRESS = 14; ERROR_CODE_UNKNOWN_MEMBER_ID = 15;
  ERROR_CODE_NOT_COORDINATOR = 16; ERROR_CODE_NOT_CONTROLLER = 17;
  ERROR_CODE_INVALID_CONFIG = 18; ERROR_CODE_INVALID_TOPIC = 19; ERROR_CODE_UNKNOWN = 20;
  ERROR_CODE_INVALID_TIMESTAMP = 21; }
```
(`ERROR_CODE_` prefix is buf STANDARD lint's enum-value-prefix rule; the SPEC §7.3 names are the
suffixes. Four codes beyond §7.3 are needed: `INVALID_CONFIG` and `INVALID_TOPIC` for CreateTopic
validation, `INVALID_TIMESTAMP` for `storage.ErrInvalidTimestamp` (D9; Kafka has the same code) and
`UNKNOWN` for unexpected server errors; recorded as D11.)

```proto

  rpc CreateTopic(CreateTopicRequest) returns (CreateTopicResponse);
  rpc DeleteTopic(DeleteTopicRequest) returns (DeleteTopicResponse);
  rpc ListTopics(ListTopicsRequest) returns (ListTopicsResponse);
  rpc Metadata(MetadataRequest) returns (MetadataResponse);
  rpc Produce(ProduceRequest) returns (ProduceResponse);
  rpc Fetch(FetchRequest) returns (FetchResponse);

  map<string,string> configs = 4; }                    // partitions/RF <= 0 => broker default
```

`ProducePartition.records` holds exactly one batch (the leader assigns offsets per batch; the base
offset in the response is that batch's). `leader_epoch = -1` means "don't check" (Kafka semantics, used by the CLI; D10). Any other value
must equal the partition's current epoch: a smaller epoch gets `FENCED_LEADER_EPOCH`; a larger one
means this broker's metadata is behind and gets `NOT_LEADER` so the client refreshes and retries
(D12; Kafka's UNKNOWN_LEADER_EPOCH is not in §7.3).

`internal.proto` gets the metadata FSM command messages (versioned, used by the local store's
local store (which persists the resulting state as JSON) and by the Raft FSM in M5):
```proto

  repeated PartitionAssignment partitions = 3; }
message PartitionAssignment { int32 partition = 1; repeated int32 replicas = 2; }

```
No internal RPC service yet (M5/M6 add it).

1 ≤ RF; 1 ≤ min_insync ≤ RF; segment_bytes ≤ 1 GiB (via `storage.LogConfig.Validate`); timeouts > 0;

## 3. `internal/metadata` — Store abstraction (§2.2)

```go
type Broker struct { ID int32; Host string; Port int32 }
type PartitionState struct { Partition int32; Replicas []int32; Leader int32; LeaderEpoch int32;
  ISR []int32; PartitionEpoch int32 }
type Topic struct { Name string; Configs map[string]string; Partitions []PartitionState }
type Snapshot struct { Brokers []Broker; ControllerID int32; Topics map[string]Topic }  // immutable copy
type ChangeKind int // TopicCreated, TopicDeleted, PartitionChanged
type Change struct { Kind ChangeKind; Topic string; Partition int32 }
type Store interface {
    Snapshot() Snapshot                            // consistent, immutable view
    Topic(name string) (Topic, bool)
    Propose(ctx context.Context, cmd *streamqv1.MetadataCommand) error // applied when it returns
    Subscribe(fn func(Change)) (unsubscribe func()) // fn runs in apply order on the store's notifier goroutine
    Close() error
}
var ErrTopicExists, ErrUnknownTopic, ErrInvalidReplicationFactor, ErrInvalidTopic, ErrNotController
```
`internal/metadata/fsm.go` holds the **deterministic** apply logic shared by local (M2) and Raft (M5)
stores: `type State` + `func (s *State) Apply(cmd) (Change list, error)`; no clock/randomness
(timestamps come in the command). Partition leader assignment (`AssignReplicas(brokers, n, rf)`:
round-robin starting at `hash(topic) % len(brokers)`, Kafka-like) is computed by the proposer and
carried in the command, so Apply is deterministic.

`internal/metadata/local`: single-node store. In-memory `State`, persisted as JSON
(`<data_dir>/metadata.json`, atomic tmp+fsync+rename+dir fsync) after every applied command.
Brokers = the local broker. Notifications are delivered by one owned goroutine reading an
unbounded-by-design-but-small queue (slice + cond), stopped by `Close`.

Topic name rules (Kafka): 1–249 chars of `[a-zA-Z0-9._-]`, not `.` or `..`.

## 5. `internal/broker` — glue (ReplicaManager)

New package (not in the CLAUDE.md layout list; D13): owns `storage.Manager`, `map[tp]*Partition`,
the HW checkpoint file and the metadata subscription. On `TopicCreated` it creates logs and calls
`BecomeLeader`; on `TopicDeleted` it closes partitions and deletes their dirs (storage
`Manager.DeleteLog`: remove from map, close, rename dir to `<dir>.<n>.delete`, remove async in
`Run`; leftovers removed at startup). `Run(ctx)` runs the storage manager loop and the HW checkpoint
loop (5s) under an errgroup; `Close` writes the final HW checkpoint and closes storage.

Fetch long-poll (`Broker.Fetch`): read every requested partition once; if total bytes ≥ min_bytes or
any partition errored, return; else wait on the union of the partitions' `HWChanged()` channels,
`max_wait_ms` timer, or ctx; on wake re-read (loop until satisfied or deadline). No polling. A
fetch at `offset == HW` returns empty; `offset > LEO` or `< logStart` → `OFFSET_OUT_OF_RANGE`.

Topic deletion uses storage support added in this milestone: `Manager.DeleteLog(ctx, tp)`.

## 6. `internal/server` — gRPC handlers (thin)

`server.New(broker, store, cfg, logger)` implements `StreamQServiceServer`: validates (nil/negative
fields, unknown acks → `codes.InvalidArgument`), delegates, and maps sentinel errors to `ErrorCode`s
in **one** function `errorCode(error) ErrorCode` (table-tested). Per-partition errors go in the
response; gRPC status only for transport/invalid requests. `acks=0` still runs the append but the
handler returns immediately (response with `NONE`).

## 7. Binaries

- `cmd/streamq-broker`: cobra root; flags = `--config` + one flag per scalar config key; loads
  config, opens store + broker + gRPC server, serves until SIGINT/SIGTERM (signal.NotifyContext),
  then `GracefulStop` (bounded by 10s, then `Stop`), broker `Close` (flush + checkpoints).
- `cmd/streamqctl`: cobra; global `--bootstrap` (default `localhost:9092`), `--timeout`.
  `topics create|delete|list|describe`, `produce --topic [--key-separator ':'] [--acks]` (lines on
  stdin; keyed via murmur2, unkeyed round-robin per line batch), `consume --topic [--partition]
  [--from-beginning|--offset] [--max-messages] [--follow]`. Output via `fmt.Fprint*(cmd.OutOrStdout())`.
  Commands live in `cmd/streamqctl/*.go` with a testable `newRootCmd(io.Reader, io.Writer)`.

## 8. `internal/partitioner` (SPEC §7.4)

`Murmur2(data []byte) int32` (Kafka's exact algorithm, seed 0x9747b28c) and
`ForKey(key []byte, n int32) int32 = (Murmur2(key) & 0x7fffffff) % n`. Test vectors from Kafka's
`UtilsTest` (e.g. murmur2("21") etc.) to guarantee compatibility. Sticky partitioner is client-side
(M3).

## 9. Tests

- **proto/server**: `errorCode` table; handler validation table.
- **config**: defaults validate; file + env + flag precedence table; unknown YAML key rejected;
  every validation rule has a failing case; `LogConfig` overrides.
- **metadata**: State.Apply table (create, duplicate → ErrTopicExists, delete unknown, RF > brokers
  → ErrInvalidReplicationFactor, invalid names); AssignReplicas properties; local store persists and
  reloads; Subscribe order; Close stops the notifier (goleak).
- **partition**: epoch checks table (−1, equal, lower → fenced, higher → not leader); HW = LEO after
  append; consumer Read never returns data ≥ HW (HW set manually below LEO via a test hook);
  HWChanged fires on advance; acks=all with min.insync > ISR → ErrNotEnoughReplicas, nothing appended.
- **broker**: Fetch long-poll — returns immediately with data; blocks until an append arrives
  (signal via append in another goroutine, no sleep; asserted with a channel); returns empty after
  max_wait (fake short wait: 50ms, measured lower bound only); min_bytes respected; topic delete
  removes dirs; restart restores HW from checkpoint.
- **server (bufconn)**: CreateTopic/Metadata/Produce/Fetch/ListOffsets end-to-end over gRPC
  `bufconn`, including UNKNOWN_TOPIC_OR_PARTITION, TOPIC_ALREADY_EXISTS, INVALID_REPLICATION_FACTOR
  (RF=2 on one broker), MESSAGE_TOO_LARGE, CORRUPT_MESSAGE, OFFSET_OUT_OF_RANGE, FENCED_LEADER_EPOCH,
  ListOffsets earliest/latest/timestamp.
- **streamqctl**: commands against an in-process bufconn/loopback broker (topics create/list/describe/
  delete, produce from a reader, consume N messages).
- **Integration (`test/integration`, tag `integration`)** — §9: start an in-process broker on
  `127.0.0.1:0` with a temp dir; create topic (6 partitions); produce 100k records with 1000 keys,
  value = `key/seq`, batched per partition (e.g. 500 records/batch), keyed with `partitioner.ForKey`;
  consume every partition from 0 to HW; verify count = 100k, each key appears in exactly one
  partition and its seqs are 0..n-1 in order; **stop the broker (graceful), start a new one on the
  same dir**, re-read everything and verify identical; plus a second scenario that kills without
  `Close` (storage files left unflushed but process-level data intact) and verifies recovery.
- goleak `TestMain` in every package with tests.

## 11. Decisions
- D10 Produce/Fetch/ListOffsets `leader_epoch = -1` skips the epoch check.
- D11 Extra error codes INVALID_CONFIG, INVALID_TOPIC, UNKNOWN.
- D12 Request epoch > known epoch → NOT_LEADER (metadata behind); < known → FENCED_LEADER_EPOCH.
- D13 New `internal/broker` package (replica manager glue between storage, partitions, metadata and
  server), keeping `internal/server` thin.
- D14 Topic deletion renames the partition dir to `<dir>.<unique>.delete` and removes it in the
  background; leftovers are removed at startup (Kafka).
- D15 Fsync of HW checkpoint every 5s and on shutdown; on restart HW = min(checkpoint, LEO), and in
  single-node mode it immediately advances to LEO.

## Revision 1 (after plan-review round 1)

These rules supersede anything above that conflicts with them.

- **R1 (finding 1)** `buf.yaml` excepts `ENUM_ZERO_VALUE_SUFFIX`, so `ERROR_CODE_NONE = 0` stays
  (zero = success; an unset code must never read as failure). The service is named
  `StreamQService`, because buf STANDARD requires the `Service` suffix, rather than SPEC §7.1's
  `StreamQ`. Both are recorded in D10, which already passes `make gen`.
- **R2 (finding 2) Defaults** SPEC §10 defaults are kept (RF 3, min.insync 2). CreateTopic does
  **not** check min.insync against RF (Kafka). acks=all on RF=1 with min.insync=2 returns
  `NOT_ENOUGH_REPLICAS` and appends nothing (tested). `deploy/single-node.yaml` ships with
  `replication_factor: 1, min_insync_replicas: 1`. Every test fixture sets RF 1 / min.insync 1
  explicitly unless it tests this case. Recorded in D16.
- **R3 (finding 3) Startup handoff** `metadata.Store.Subscribe(fn func(context.Context, Change))
  (Snapshot, func())` registers the subscriber and returns the snapshot it starts from,
  atomically under the store lock. Every later change is delivered exactly once, in order.
  `broker.Open(ctx, ...)` subscribes, opens every local partition of the returned snapshot
  (`GetOrCreateLog` + `BecomeLeader`), cleans stray dirs (R5), and only then does
  `cmd/streamq-broker` start serving gRPC. Change handlers are idempotent: creating an existing
  partition or deleting an unknown one is a no-op.
- **R4 (finding 4) Create waits for readiness** `Broker.WaitTopicReady(ctx, topic) error` blocks
  until every local partition of the topic is open as leader, or until ctx ends. It waits on a
  broker-level "partitions changed" channel (closed and replaced on each change); no polling. The
  CreateTopic handler calls it after `Propose`, bounded by the request ctx (deadline
  `REQUEST_TIMED_OUT`). DeleteTopic likewise waits for local removal. Test: 50× CreateTopic
  immediately followed by Produce over bufconn, with zero failures.
- **R5 (finding 5) Delete/recreate safety**
  - `CreateTopicCommand` gains `string topic_id = 4`: 16 random bytes in hex, generated by the
    proposer (the server handler), so Apply stays deterministic.
  - Each partition dir holds `partition.metadata` (`version: 0\ntopic_id: <id>\n`, written
    atomically on creation; Kafka's file of the same name).
  - At startup the broker renames to `<dir>.<topic_id-or-"stray">.delete` every partition dir
    that is either not in the snapshot or whose `partition.metadata` topic_id differs.
  - `storage.Manager.DeleteLog(ctx, tp)` closes the log, drops tp from `recoveryPoints` and
    rewrites the recovery-point checkpoint (fsynced) **before** renaming the dir. The broker drops
    tp from its HW map and rewrites `replication-offset-checkpoint` the same way. `*.delete` dirs
    are removed by `Manager.Run` and at startup.
  - The local store applies each command to a deep copy, persists it (tmp + fsync + rename +
    dir fsync), and only then swaps the copy in and notifies. A persist failure returns an error
    and leaves memory unchanged.
  - Tests: (a) write metadata delete+recreate but leave the old dir (simulating a crash before the
    rename), restart, and check the new topic is empty; (b) delete, recreate, write, reopen
    without a checkpoint, and check a full CRC recovery runs (no ErrCorruptLog, no stale recovery
    point); (c) a persist failure leaves the in-memory state unchanged.
- **R6 (finding 6) Long-poll**
  - For each round, `Broker.Fetch` first **captures** every requested partition's `HWChanged()`
    channel, then reads. If the reads don't satisfy the request, it waits with one
    `reflect.Select` over the captured channels, the timer, ctx and the broker's `done` channel.
    No helper goroutines.
  - The timer comes from an injected `Clock` interface (`After(d) <-chan time.Time`; the real one
    wraps time).
  - Test hook `afterRead func()` lets a test append between the read and the wait; the fetch must
    return the new data without waiting for max_wait. The empty-after-max_wait test uses the fake
    clock.
- **R7 (finding 7) acks** acks=0 appends **synchronously** in the handler exactly like acks=1. The
    response returns `base_offset = -1` and suppresses error codes (Kafka). On a single node
    acks=1 and acks=all return right after the append (HW = LEO), after the min.insync check.
- **R8 (finding 8) Kill scenario** The integration test builds `cmd/streamq-broker` into
  `t.TempDir()` with `go build` and runs it as a subprocess (`exec.CommandContext`) with
  `listen_addr: 127.0.0.1:0`. The broker logs a JSON `"msg":"serving","addr":...` line on stderr,
  which the test parses for the address. The test produces with acks=all and records every acked
  batch, sends SIGKILL, restarts on the same dir, and verifies that every acknowledged record is
  present and that per-key order holds. The in-process graceful scenario (Close and reopen) stays
  as well. No two brokers ever share a dir concurrently.
- **R9 (finding 9) Contract completeness** The contract commit contains real signatures with stub
  bodies (`errors.New("unimplemented")`) for:
  - `config.Default`, `config.Load`, `Config.Validate`, `config.TopicConfig` (`{Log
    storage.LogConfig; MinInsyncReplicas int32}`), `config.TopicConfigKeys` (allowed override
    keys) and `config.ResolveTopicConfig(defaults, overrides) (TopicConfig, error)`;
  - `metadata` types, `Store`, `Change` (`Kind`, `Topic`, `TopicID`, `Partitions []PartitionState`),
    `State`, `NewState`, `State.Apply`, `State.Clone`, `AssignReplicas`, `ValidateTopicName` and
    the errors;
  - `metadata/local.Open(ctx, dataDir string, self Broker, logger) (*Store, error)`;
  - `partitioner.Murmur2`, `partitioner.ForKey`;
  - `cmd/streamqctl` `newRootCmd(in io.Reader, out, errOut io.Writer) *cobra.Command`.

  Stubs import cobra, yaml.v3, grpc, protobuf and errgroup so `go mod tidy` keeps them. go.mod
  and go.sum are committed in the contract. Implementers must not modify them and must report any
  new dependency as a CONTRACT ISSUE.
- **R10 (finding 10) Shutdown**
  - `max_wait_ms` is capped at 30 s; `Broker.Close` closes `done`, which wakes every waiting
    fetch.
  - Order: signal, then `GracefulStop` (10 s bound, then `Stop`), then `Close` the broker. Close
    does: close `done`, cancel the Run ctx, wait for the errgroup (`Manager.Run` and the HW
    checkpoint loop), write the final HW checkpoint, unsubscribe, `Manager.Close`. The store is
    closed last.
- **R11 (finding 11) Error mapping (one table, table-tested)** Unmatched errors fall to `UNKNOWN`
  and are logged at ERROR.

  | sentinel | ErrorCode |
  |---|---|
  | `metadata.ErrUnknownTopic`, `storage.ErrClosed`, unknown partition | `UNKNOWN_TOPIC_OR_PARTITION` |
  | `metadata.ErrTopicExists` | `TOPIC_ALREADY_EXISTS` |
  | `metadata.ErrInvalidReplicationFactor` | `INVALID_REPLICATION_FACTOR` |
  | `metadata.ErrInvalidTopic` | `INVALID_TOPIC` |
  | `config.ErrInvalidConfig` | `INVALID_CONFIG` |
  | `partition.ErrNotLeader` | `NOT_LEADER` |
