# M4 — Consumer groups (single node) (plan)

SPEC refs: §5 (all), §7.1 (group RPCs), §7.3 (ILLEGAL_GENERATION, REBALANCE_IN_PROGRESS,
UNKNOWN_MEMBER_ID, NOT_COORDINATOR), §8 FR6, FR11 (`streamqctl groups list/describe/lag`), §9 M4.
Acceptance (§9): 3 consumers on 6 partitions: no double assignment; killing one rebalances within
the session timeout; a stale-generation commit is rejected; a restarted group resumes from its
committed offsets.

Out of scope: controller failover / Raft (M5 — on a single node the local broker is always the
coordinator), cooperative/incremental rebalancing, static membership, offset retention/expiry.

No new dependencies.

---

## 1. Protocol (server-side assignment, SPEC §5)

The coordinator (= controller = the local broker in M4) owns membership in memory and computes
assignments itself (SPEC: "computes assignments"), unlike Kafka's leader-client assignment.

Group state machine (per group, Kafka-like):
- **Empty** — no members (may still have committed offsets).
- **PreparingRebalance** — a join, leave or member expiry happened; join requests are parked. It
  completes when every current member has (re)joined, or when the rebalance timeout (max of the
  members' `rebalance_timeout_ms`) expires — members that did not rejoin are removed. A group going
  from Empty to PreparingRebalance first waits `group_initial_rebalance_delay_ms` (default 3s,
  Kafka; tests set it low) so several consumers starting together land in one generation.
- **CompletingRebalance → Stable** — on completion: `generation++`, pick the assignor (first in the
  first member's preference list that every member supports; default `range`), compute the
  assignment over the union of subscriptions (partition counts from metadata), answer every parked
  JoinGroup with `{generation, member_id, assignor, assignment}`, go Stable. `SyncGroup` returns the
  member's assignment for the current generation (kept for protocol shape, SPEC §5; a member whose
  generation is stale gets ILLEGAL_GENERATION, during a rebalance REBALANCE_IN_PROGRESS).
- **Heartbeat** `{group, member, generation}` → NONE in Stable with the current generation;
  REBALANCE_IN_PROGRESS while PreparingRebalance (member must rejoin); ILLEGAL_GENERATION for an old
  generation; UNKNOWN_MEMBER_ID for an unknown member. Every heartbeat/join/sync resets the member's
  session deadline.
- **Session expiry**: a member whose deadline (`session_timeout_ms` from its JoinGroup, bounded by
  the broker's `group_session_timeout_ms` as the max) passes is removed → rebalance. Timers use an
  injected clock.
- **LeaveGroup** → remove member → rebalance (or Empty if last).
- **CommitOffset** `{group, member, generation, offsets}`: generation −1 + empty member = standalone
  commit, allowed only if the group has no members (Kafka); unknown member → UNKNOWN_MEMBER_ID;
  PreparingRebalance → REBALANCE_IN_PROGRESS; generation mismatch → ILLEGAL_GENERATION; else the
  offsets are committed **through the metadata store** (SPEC §5) and the response returns after the
  command is applied.
- **FetchOffset** `{group, partitions (empty = all)}` → committed offsets (−1 if none).
- **FindCoordinator** `{group}` → `{coordinator broker id, host, port}`; in M4 always self. Non-
  coordinators would answer NOT_COORDINATOR (wired via a `IsController()` check on the store, always
  true for the local store).

Assignors (`internal/group/assign.go`), pure functions over sorted member ids and sorted
partitions, deterministic:
- **range** (Kafka RangeAssignor): per topic, partitions split into contiguous ranges over the
  members subscribed to it (sorted); the first `n % m` members get one extra.
- **roundrobin**: all (topic, partition) pairs sorted, dealt round-robin over members, skipping
  members not subscribed to that topic.

## 3. Metadata (`internal/metadata`)
- `State.Groups map[string]map[TopicPartition]int64` (JSON-persisted), `Snapshot.Groups` (deep
  copy), `State.Apply(commit_offsets)`: validates group id non-empty and that each partition exists
  (else ErrUnknownTopic) and offset ≥ 0; emits `Change{Kind: OffsetsCommitted, Group: id}`.
- Deleting a topic drops its committed offsets in every group (Kafka deletes them with the topic).
- `metadata.CommittedOffsets(snap, group) map[...]int64` helper.

## 4. Coordinator (`internal/group`)
```go
type Clock interface { Now() time.Time; AfterFunc(d, f) (stop func() bool) }
type Config struct { MaxSessionTimeout, InitialRebalanceDelay time.Duration; BrokerID int32 }
type Coordinator struct { ... }  // owns groups map, one mutex, timers via Clock
func New(cfg Config, store metadata.Store, clock Clock, logger) *Coordinator
func (c *Coordinator) Join(ctx, req JoinRequest) (JoinResult, error)  // blocks until the rebalance completes or ctx ends
func (c *Coordinator) Sync(group, member string, gen int32) (Assignment, error)
func (c *Coordinator) Heartbeat(group, member string, gen int32) error
func (c *Coordinator) Leave(group, member string) error
func (c *Coordinator) Commit(ctx, group, member string, gen int32, offsets map[TopicPartition]int64) error
func (c *Coordinator) Fetch(group string, tps []TopicPartition) (map[TopicPartition]int64, error)
func (c *Coordinator) List() []string; Describe(group) (GroupDescription, error)
func (c *Coordinator) Close()  // stops timers, fails parked joins with ErrCoordinatorClosed
var ErrUnknownMemberID, ErrIllegalGeneration, ErrRebalanceInProgress, ErrNotCoordinator,
    ErrInvalidGroup, ErrCoordinatorClosed
```
Concurrency: one `Coordinator.mu` guards all groups (group ops are cheap); parked JoinGroups wait on
a per-generation `done` channel closed when the rebalance completes (or ctx/Close). Timer callbacks
(session expiry, rebalance timeout, initial delay) take `mu`, check a per-member/per-rebalance
token to ignore stale timers, and act. Commits call `store.Propose` **outside** `mu` after
validating generation under `mu`; a rebalance racing the propose is acceptable (Kafka's commit is
also validated then written). Partition counts for assignment come from `store.Snapshot()`; topics
that don't exist contribute no partitions.

## 5. Server
Handlers in `internal/server/group.go`, delegating to the Coordinator, errors mapped in
`errorCode` (new sentinels). The coordinator is created in `internal/node` and closed after the
gRPC server stops and before the broker.

## 6. Client (`pkg/client/group.go`)
```go
type GroupConsumerConfig struct { GroupID string; Topics []string; SessionTimeout (10s);
  RebalanceTimeout (30s); HeartbeatInterval (3s); AutoCommit bool (default true via
  DisableAutoCommit); AutoCommitInterval (5s); AutoOffsetReset; Assignors []string (["range"]);
  Consumer ConsumerConfig }
func NewGroupConsumer(c *Client, cfg GroupConsumerConfig) (*GroupConsumer, error)
func (g *GroupConsumer) Poll(ctx) ([]Record, error)   // joins/rejoins as needed
func (g *GroupConsumer) Commit(ctx) error             // commits current positions (sync)
func (g *GroupConsumer) Assignment() []TopicPartition; Generation() int32
func (g *GroupConsumer) Close(ctx) error              // commit (if auto), LeaveGroup, stop heartbeats
```
- `Poll`: if not a member or rebalance flagged → (auto-commit current positions if member) →
  FindCoordinator → JoinGroup (blocks) → SyncGroup → assign the inner `Consumer`, FetchOffset for
  the assignment, Seek to committed (or leave unset → `auto.offset.reset`). Then delegate to the
  inner Consumer's Poll; auto-commit if `AutoCommitInterval` elapsed (clock injectable).
- Heartbeats: one goroutine per membership generation, owned by the GroupConsumer, every
  `HeartbeatInterval`; REBALANCE_IN_PROGRESS / ILLEGAL_GENERATION / UNKNOWN_MEMBER_ID set a
  `needsRejoin` flag (UNKNOWN_MEMBER_ID also clears member id); stopped on rejoin/Close (context +
  WaitGroup, goleak-clean).
- NOT_COORDINATOR / transport errors → rediscover the coordinator with backoff.
- Commit errors ILLEGAL_GENERATION / UNKNOWN_MEMBER_ID / REBALANCE_IN_PROGRESS → rejoin; the
  commit is lost (at-least-once).

  subscriptions; roundrobin), property: every partition assigned exactly once to a subscribed
  member; determinism.
- **coordinator** (fake clock, no sleeps): single member join → gen 1, all partitions; 3 members
  join within the initial delay → one generation, disjoint cover; a 4th joins → rebalance, existing
  members get REBALANCE_IN_PROGRESS on heartbeat, rejoin, new generation; member that does not
  rejoin within the rebalance timeout is removed; session expiry → removal → rebalance; leave;
  heartbeat/sync/commit error codes per §1 (stale generation → ILLEGAL_GENERATION, unknown member,
  during rebalance); standalone commit rules; commits persisted through a real local store and
  visible in Fetch after re-creating the coordinator (simulated restart); topic deletion drops
  offsets; Close fails parked joins; goleak.
- **metadata**: Apply commit_offsets (+ invalid cases), persistence round trip, delete-topic drop.
- **server**: error-code mapping rows; gRPC end-to-end join/sync/heartbeat/commit/fetch.
- **client GroupConsumer** (fake coordinator RPCs on bufconn): join/sync/assign/fetch-offset/seek,
  heartbeat rejoin on REBALANCE_IN_PROGRESS, auto-commit interval (fake clock), commit on Close +
  LeaveGroup, coordinator rediscovery on NOT_COORDINATOR.
- **CLI**: groups list/describe/lag against a fake server.
- **Integration (§9)** — real in-process broker, group initial delay 200 ms, session 2 s, heartbeat
  200 ms:
  1. 3 GroupConsumers on a 6-partition topic: after stabilising, assignments are disjoint and cover
     all 6 (no double assignment), 2 each with range.
  2. Kill one (stop heartbeats without LeaveGroup — `closeWithoutLeave` test hook): within the
     session timeout (+ rebalance) the remaining two own all 6 partitions (asserted with
     `require.Eventually` bounded by session timeout + 2 s).
  3. Stale-generation commit: commit with generation−1 → ILLEGAL_GENERATION.
  4. Produce 600 records, consume with the group to the end with commits, close all; start a new
     group consumer with the same id → it starts at the committed offsets (receives only records
     produced after, none duplicated), also after a broker restart (offsets in metadata.json).

## Revision 1 (after plan-review round 1)

These rules supersede anything above that conflicts with them.

- **R1 (finding 1) Commit validation order (Kafka)**:
  1. A standalone commit (gen −1, empty member) is allowed only when the group has no members.
  2. An unknown member gets UNKNOWN_MEMBER_ID.
  3. A generation mismatch gets ILLEGAL_GENERATION.
  4. The current generation commits normally in **PreparingRebalance or Stable**.

  The coordinator has no separate "completing" state: completion is atomic under `mu`. So
  REBALANCE_IN_PROGRESS is never returned for commits.

  Tests: a commit with the current generation during PreparingRebalance succeeds. Closing three
  consumers one after another loses no commits.
- **R2 (finding 2) Keep-alive while parked** (Kafka `shouldKeepAlive`): a member parked in
  JoinGroup is not subject to session expiry. When a rebalance completes, every member's session
  deadline is reset to completion time + its session timeout. Fake-clock test: a rebalance waits
  longer than the session timeout and the parked members survive.
- **R3 (finding 3) Join deadlines and abandoned joins**:
  - The client gives JoinGroup an RPC deadline of `max(RequestTimeout, RebalanceTimeout + 5s)`,
    and passes the broker's initial delay through as well (`RebalanceTimeout` must be ≥ the initial
    delay; D25).
  - In the coordinator, if a parked Join's ctx ends and that request created the member (empty
    `member_id`), the member is removed and the coordinator re-checks whether the rebalance can
    complete. A member that existed before simply stops being parked, and its keep-alive ends.
  - A Join with an unknown non-empty `member_id` gets UNKNOWN_MEMBER_ID, and the client clears its
    id and rejoins.
  - Tests cover both cases.
- **R4 (finding 4) Shutdown**: `Coordinator.BeginShutdown()` is called in `node.Close` before
  `GracefulStop`, next to `broker.BeginShutdown()`. It fails parked joins with
  `ErrCoordinatorClosed` and rejects new requests with it. The server maps `ErrCoordinatorClosed`
  to NOT_COORDINATOR, so clients rediscover; there is a test row for it. `Close()` stops the timers
  and waits for running callbacks (R10).
- **R5 (finding 5) Persisted layout**: `State.Groups` is `map[string]GroupOffsets`, with
  `GroupOffsets = map[string]map[int32]int64` (group → topic → partition → offset). This is
  JSON-encodable, because `encoding/json` encodes integer keys as decimal strings; it is already
  implemented and tested.
  - `NewState` and `local.load` set `Groups` to an empty map when nil.
  - Test: a pre-M4 `metadata.json` without `groups` loads, and commits then persist.
  - Recorded in D28 as an additive on-disk change (new optional key in `metadata.json`).
- **R6 (finding 6) Topic changes and per-partition commit results**:
  - The coordinator subscribes to the store. On TopicCreated or TopicDeleted for a topic in any
    member's subscription, that group moves to PreparingRebalance.
  - `CommitOffsetResponse` gains `repeated OffsetCommitResult results = 3` with
    `{topic, partition, error_code}` (Kafka shape). The coordinator drops partitions of unknown
    topics before proposing, reports them as UNKNOWN_TOPIC_OR_PARTITION, and commits the rest.
    `error_code` stays for request-level errors.
  - Tests: a topic created after the group stabilised gets assigned. A commit after a subscribed
    topic is deleted still persists the other partitions.
- **R7 (finding 7)** Members **not** parked still expire on their session deadline during
  PreparingRebalance. Each removal re-checks whether the rebalance can complete (tested).
- **R8 (finding 8) Integration hooks**: there are no test hooks in the public API.
  - A killed member is a raw-gRPC member (JoinGroup/SyncGroup/Heartbeat via stubs) that then stops
    heartbeating.
  - The stale-generation commit uses a raw-gRPC member that was in generation N, rejoined into N+1,
    and then commits with N, getting ILLEGAL_GENERATION.
  - `GroupConsumer.MemberID()` is added as a documented, concurrency-safe accessor.
- **R9 (finding 9)** `Assignment()`, `Generation()` and `MemberID()` are safe for concurrent use
  (mutex). The integration test asserts disjoint, complete assignments only when every member
  reports the same generation, and cross-checks `DescribeGroup`.
- **R10 (finding 10)** Coordinator timer callbacks are tracked by a WaitGroup. They check a
  `closed` flag under `mu`, and `Close` waits for them.
- **R11 (finding 11)** Coordinator check: `store.Snapshot().ControllerID == cfg.BrokerID`, else
  NOT_COORDINATOR. There is no new Store method.
- **R12 (finding 12) Mappings**:
  - ErrInvalidGroup (empty group id, no assignor in common, unknown assignor) → gRPC
    InvalidArgument;
  - ErrCoordinatorClosed and ErrNotCoordinator → NOT_COORDINATOR;
  - ErrUnknownMemberID → UNKNOWN_MEMBER_ID;
  - ErrIllegalGeneration → ILLEGAL_GENERATION;
  - ErrRebalanceInProgress → REBALANCE_IN_PROGRESS.

  All are rows in `errors_test.go`.
- **R13 (finding 13) Timeouts** (D25):
  - `group_rebalance_timeout_ms` is the server default when a request sends ≤ 0.
  - A request whose session timeout is ≤ 0 gets `group_session_timeout_ms`.
  - A session timeout **above** `group_session_timeout_ms` is clamped to it rather than rejected:
    there is no INVALID_SESSION_TIMEOUT code in §7.3, and clamping keeps clients working.
- **R14 (finding 14) Proto**:
  - Every new response has `string error_message`.
  - `ListGroupsResponse` has `error_code` and `error_message`.
  - ListGroups and DescribeGroup are recorded in D29 as beyond §7.1, for FR11.
- **R15 (finding 15)** `List`/`Describe` cover the union of in-memory groups and groups with
  committed offsets in the snapshot. A group with offsets only shows as state `Empty`,
  generation 0.
- **R16 (finding 16) Edge cases**:
  - Members with no assignor in common, or naming an unknown assignor, are rejected at join with
    ErrInvalidGroup.
  - The chosen assignor is the first entry of the **earliest-joined** member's list that every
    member supports.
  - A Stable member that rejoins with the same generation-current subscription and assignors gets
    its current assignment back without a rebalance (Kafka).
  - A rejoin with a changed subscription triggers a rebalance.
- **R17 (finding 17) Split ownership**:
  - Package C uses a wrapper fake in `groups_test.go` that embeds the CLI's existing `fakeServer`
    and implements the group RPCs. `harness_test.go` is not edited.
  - D also owns `internal/server/server.go` (New signature, errorCode), `server_test.go`,
    `errors_test.go` and `internal/node/node.go`.
- **R18 (finding 18) Client tests**:
  - The GroupConsumer uses the `pkg/client` `clock` interface for heartbeats and auto-commit, and
    its tests use the producer's `fakeClock`.
  - Tests cover `auto.offset.reset` earliest and latest for a group without committed offsets, and
    a committed offset that is out of range after retention (OFFSET_OUT_OF_RANGE, then reset per
    policy, handled by the inner Consumer).
