# M10 — Benchmarks & docs (plan)

SPEC §9 M10:
- a `bench/` load tool reporting throughput and p50/p99/p999;
- a README with an architecture diagram, a results table, and a design trade-offs section
  linking `docs/DECISIONS.md`.

NFR1 and NFR2 are goals, not gates. Actual numbers are measured and documented: NFR1 is 3
brokers, RF 3, acks=all, 1 KiB, batched, ≥ 50k msgs/s; NFR2 is a single broker, acks=1, 1 KiB at
5k msgs/s with p99 < 10 ms. The code-reviewer runs alone; M10 has no failure-reviewer.

## 1. Bench tool (`bench/`)

**Layout:** `bench/cmd/streamq-bench` (main) plus `bench/internal/...` or package `bench` for
the logic, so it can be tested.

**Cluster modes**
- `-cluster inprocess:1` and `-cluster inprocess:3` start brokers in-process through
  `internal/node`, with temp data dirs on loopback and test-like fast timeouts.
  `internal/testnode` is not used, because it requires `testing.TB`.
- `-bootstrap host:port,...` targets an external cluster (for example `make cluster-up`).

**Workload flags**
- `-topic` (created if missing), `-partitions` (default 6), `-rf`, `-min-insync`;
- `-acks all|leader|none`, `-idempotent` (default true with acks=all, per D48);
- `-record-size` (default 1024), `-key-cardinality` (0 = unkeyed / sticky);
- `-rate` (msgs/s; 0 = as fast as possible), `-producers` (default 4), `-duration`, `-warmup`;
- `-linger`, `-batch-size`;
- `-consume` (also run a consumer and measure end-to-end latency from a timestamp in the
  value).

**Measurements**
- Produce latency, from the `Produce` call to the ack callback, kept per record in a
  log-bucketed histogram: about 1 % relative error, with a fixed memory bound.
- Throughput in msgs/s and MiB/s, plus error counts by kind.
- End-to-end latency when `-consume` is set.
- Percentiles p50/p99/p999 and max.
- Records from the warmup period are excluded.

**Output:** a human table on stdout through `fmt.Fprintf(os.Stdout, ...)`, and `-json <path>`
with the full result, the config and the environment (CPU, cores, RAM, OS, Go version, commit
when available).

**Presets** (`-preset`):
- `quick`: inprocess:1, acks=1, 10 s; used by `make bench`.
- `nfr1`: inprocess:3, RF 3, acks=all, 1 KiB, max rate, 6 partitions, 8 producers, 30 s.
- `nfr2`: inprocess:1, acks=1, 1 KiB, rate 5000, 30 s.
- `nfr1-nonidem`: `nfr1` with idempotence disabled, to show its cost.

**Rate limiting:** a token bucket on the injected clock, so no sleeps in tests.

**Tests:**
- percentile math against known distributions;
- the bucket error bound;
- token-bucket pacing with a fake clock;
- preset parsing;
- one short in-process smoke test (2 s, inprocess:1), tagged `integration` and run by
  `make test-int`. `test-int` gains `./bench/...`.

## 3. Decisions to add
- **D60:** the bench tool runs in-process clusters by default, because it is reproducible and
  needs no Docker. The README states that numbers are from one laptop, in-process, over loopback,
  which is optimistic compared with real networks.
- **D61:** the latency histogram uses log buckets (about 1 % error) instead of the HdrHistogram
  dependency; no new dependency is needed.

## Revision 1 (after plan-review round 1)

These rules supersede the text above where they conflict.

- **R1 (MAJOR 1) Producers and batching are explicit.**
  - `-producers N` means N independent `client.Client` + `client.Producer` pairs, each driven by
    one goroutine.
  - Every preset fixes `-linger` and `-batch-size`:
    - `nfr1`: batch 512 KiB, linger 10 ms;
    - `nfr2`: linger 1 ms, default batch;
    - `quick`: linger 5 ms.
  - The table and the JSON print every effective ProducerConfig value (Acks, idempotence, Linger,
    BatchSize, BufferMemory, MaxRequestSize) and the partition count.
  - The README results section names D21's one batch in flight per partition per producer as the
    main throughput constraint.
- **R2 (MAJOR 2) Production-like in-process clusters.**
  - In-process brokers start from `config.Default()` timeouts (Raft 1000/1000 ms, broker session
    9000 ms). Only harmless overrides apply: listeners, `MetricsAddr=""`, DataDir,
    ControlledShutdownTimeoutMs.
  - `cfg.Validate()` runs on each config.
  - `-min-insync` defaults to 2 for RF 3 (SPEC §10).
  - Before and after the measurement window the tool snapshots, from `Node.Broker()`, every
    partition's leader epoch and ISR. Any leader change, or an ISR smaller than the RF, marks the
    result **INVALID** (exit non-zero). Error counts by kind are reported.
- **R3 (MAJOR 3) No coordinated omission.**
  - With `-rate > 0`, latency is measured from the token bucket's **intended** send time. Service
    time (from the Produce call) is reported separately, along with a count of sends that fell
    behind schedule.
  - The `nfr2` linger (1 ms) is recorded next to the result.
  - A fake-clock unit test proves that a stalled Produce shows up in intended-time latency.
- **R4 (MAJOR 4) Histogram concurrency and windowing.**
  - Each producer has its own histogram shard with atomic bucket counters; shards merge at the
    end.
  - A record counts only if its (intended) send time is at or after warmup end and its ack
    arrives before the window closes. Throughput counts acks inside the window.
  - Tests: concurrent recording under `-race`, and both windowing rules.
- **R5 (MINOR 5) Cleanup.**
  - One parent `os.MkdirTemp` (`-data-dir` overrides it) is removed on every exit path.
  - `signal.NotifyContext`: SIGINT cancels the run, closes the producers, then the nodes (in
    parallel), and prints partial results.
  - The bench topic sets `retention_bytes`.
  - `-help` states the expected disk use.
- **R6 (MINOR 6)** Listeners are pre-bound on 127.0.0.1:0, the member list is built from them,
  the nodes start concurrently with `node.StartWithOptions`, and they close concurrently.
- **R7 (MINOR 7) Environment capture.**
  - The tool runs `git rev-parse HEAD` and `git status --porcelain` and records `-dirty`.
  - It also records flush_policy, the data-dir filesystem (from `/proc/mounts`), CPU, cores, RAM,
    OS, kernel and the Go version.
- **R8 (MINOR 8) Lint hygiene.**
  - Presets come from a function, not a global.
  - The JSON is written with mode 0o600.
  - goleak's `TestMain` lives in an untagged `main_test.go`.
  - `-record-size >= 16` when `-consume` is set (it embeds a timestamp).
  - acks=none latency is labelled "send latency".
- **R9 (MINOR 9) Frozen CLI contract.**
  - The contract commit adds `bench/USAGE.md` with the frozen flag names, preset names,
    `make bench` behaviour and the JSON top-level fields.
  - A reports any deviation as a CONTRACT ISSUE.
  - At integration the main session diffs `streamq-bench -help` against USAGE.md and the README.
- **R10 (MINOR 10) Profiling and compose numbers.**
  - Add a `-cpuprofile` flag. The main session profiles an nfr1 run and records in PROGRESS_LOG
    whether `store.Snapshot()` (the deferred M6 item) shows up.
  - Any compose numbers in the README are labelled "through toxiproxy".
- **R11 (MINOR 11)** acks=none reports send latency only, labelled as such.

### Decisions added
- **D62:** `nfr1` measures RF 3 with min.insync 2 (SPEC §10), not testnode's 1.
- **D63:** `nfr2` uses linger 1 ms. Kafka's `linger.ms` defaults to a few ms in recent versions;
  the client default is 5 ms (D22). A low linger matches a latency-oriented configuration, and it
  is recorded next to the result.

## Revision 2 (MINORs adopted from plan-review round 2)
- **R12. Tail windowing.** A record's latency counts if its intended send time is in
  [warmupEnd, windowEnd), whenever its ack arrives. After the window, acks keep being collected
  for a bounded drain (the lesser of the producer delivery timeout and 30 s). Records still
  unacked after the drain are reported as timeouts. Throughput counts only acks inside the
  window. A unit test covers a stall that starts in the window and ends after it.
- **R13. Detect temporary ISR changes.**
  - In-process: before and after the window, record each partition's (LeaderEpoch,
    PartitionEpoch) from the metadata store (the node's Raft store, or the single-node local
    store). Any change marks the run INVALID.
  - `-bootstrap` mode: use `client.Admin` describe (leader epoch and ISR). This mode only catches
    changes still in place at the end, as USAGE.md states.
- **R14. Disk.** `retention_bytes` is dropped (retention runs every 5 min). `-help` estimates disk
  use as rate × size × RF × time. A `statfs` free-space check refuses to start when the estimate
  exceeds the free space.
- **R15. Ownership.**
  - The contract commit carries the Makefile changes (`bench` target, `test-int` gains
    `./bench/...`).
  - A must not edit `bench/USAGE.md`.
  - A builds payloads deterministically (no `math/rand` in non-test code). Any lint exclusion it
    needs is a CONTRACT ISSUE.
- **R16. Spelling and rate.** The presets use `leader`. `-rate` is the total across all producers,
  enforced by **one shared token bucket**; recorded in the JSON.
- **R17. Memory.** Peak RSS (from `/proc/self/status` VmHWM) goes into the environment block. The
  README caveat names the memory-constrained WSL2 host.
