## 1. `internal/record` — batch + record encoding

Files: `doc.go`, `batch.go` (layout, accessors, header parse), `builder.go`, `decode.go`
(Validate, Records, SplitBatches), `varint.go`, `*_test.go`, `fuzz_test.go`.

```go
const (
    HeaderSize   = 61         // §3.5
    Magic  int8  = 1
    NoProducerID int64 = -1
    NoSequence   int32 = -1
    // byte offsets of every header field (BaseOffsetOffset=0, BatchLengthOffset=8,
    // LeaderEpochOffset=12, MagicOffset=16, CRCOffset=17, AttributesOffset=21, ...,
    // RecordCountOffset=57); CRC covers [AttributesOffset, end).
)
var (
    ErrCorrupt   = errors.New("record: corrupt batch")      // CRC/length/magic/record mismatch
    ErrTruncated = errors.New("record: truncated batch")    // fewer bytes than batchLength says
    ErrTooLarge  = errors.New("record: batch too large")    // > max.message.bytes
)
type BatchHeader struct { BaseOffset int64; BatchLength int32; LeaderEpoch int32; Magic int8;
    CRC uint32; Attributes int16; LastOffsetDelta int32; FirstTimestamp, MaxTimestamp int64;
    ProducerID int64; ProducerEpoch int16; BaseSequence int32; RecordCount int32 }
type Header struct { Key string; Value []byte }   // record header
type Record struct { Offset int64; Timestamp int64; Key, Value []byte; Headers []Header }
                    // nil Key/Value = null (-1 length); empty non-nil = zero length

// Batch is one encoded batch (on disk == on wire). Accessors assume len(b) >= HeaderSize,
// i.e. the batch came from ParseHeader/Validate/Builder.
type Batch []byte
func (b Batch) BaseOffset() int64; SetBaseOffset(int64); LeaderEpoch() int32; SetLeaderEpoch(int32)
func (b Batch) LastOffset() int64; NextOffset() int64; RecordCount() int32; MaxTimestamp() int64
func (b Batch) FirstTimestamp() int64; ProducerID() int64; ProducerEpoch() int16; BaseSequence() int32
func (b Batch) Size() int                          // 12 + batchLength
func (b Batch) Records() ([]Record, error)         // full decode, absolute offsets/timestamps

func ParseHeader(buf []byte) (BatchHeader, error)       // needs HeaderSize bytes; checks magic,
    // batchLength >= HeaderSize-12, recordCount >= 1, lastOffsetDelta == recordCount-1
func Validate(b []byte, maxBytes int) (Batch, error) // ParseHeader + exact length + CRC-32C
    // + every record decodes, offsetDeltas are 0..n-1 in order, no trailing bytes;
    // len > maxBytes -> ErrTooLarge (checked first, before CRC)
func SplitBatches(buf []byte) ([]Batch, error)     // header+length framing only (no CRC)

type BuilderOptions struct { ProducerID int64; ProducerEpoch int16; BaseSequence int32 }
func NewBuilder(opts BuilderOptions) *Builder
func (b *Builder) Append(timestamp int64, key, value []byte, headers []Header)
func (b *Builder) Len() int; func (b *Builder) Size() int     // encoded size so far
func (b *Builder) Build() (Batch, error)          // error if empty; baseOffset=0, leaderEpoch=0
```
Details: firstTimestamp = first record's timestamp, timestampDelta may be negative (zig-zag),
maxTimestamp = max over records. CRC-32C via `crc32.MakeTable(crc32.Castagnoli)` called at use
(stdlib caches it; no package-level var). `baseOffset`, `batchLength`, `leaderEpoch`, `magic` sit
before the CRC range, so the leader can stamp offset/epoch without recomputing the CRC (Kafka).
Varints use `encoding/binary` `AppendVarint`/`Varint` (zig-zag); 32-bit fields are range-checked
on decode (`ErrCorrupt` on overflow). All length fields are bounds-checked against the remaining
buffer before slicing, so a hostile length can never panic or over-allocate.

Tests (table-driven): round trip (null vs empty key/value, headers, 1 and 1000 records,
out-of-order timestamps, 512 KiB value); every CRC-covered byte flipped → `ErrCorrupt`; baseOffset /
leaderEpoch rewrite keeps CRC valid; truncated at every length → `ErrTruncated`/`ErrCorrupt`, never
panic; > maxBytes → `ErrTooLarge`; recordCount / lastOffsetDelta / offsetDelta mismatch and trailing
bytes → `ErrCorrupt`; varint boundary values (int32/int64 min/max); `SplitBatches` on 3 concatenated
batches and on a cut-off tail. **`FuzzValidate`**: seeded with valid batches; must never panic; when
`Validate` succeeds, rebuilding from `Records()` reproduces the same CRC-covered bytes.

### 2.2 Indexes (`index.go`, `timeindex.go`, `mmap.go`)
```go
// offset index: 8-byte big-endian entries (relOffset uint32, position uint32)
func openOffsetIndex(path string, baseOffset int64, maxBytes int) (*offsetIndex, error)
func (i *offsetIndex) append(offset int64, pos uint32) error // ErrIndexFull; offset must increase
func (i *offsetIndex) lookup(offset int64) (int64, uint32)   // largest entry <= offset, else (base,0)
func (i *offsetIndex) truncateTo(offset int64)               // drop entries with offset >= offset
func (i *offsetIndex) reset(); entries() int; lastOffset() int64; isFull() bool
func (i *offsetIndex) sanityCheck(logSize int64) error       // entries strictly increasing, pos < logSize
func (i *offsetIndex) trim() error   // ftruncate file to entries*8 (mapping kept; never touched past n)
func (i *offsetIndex) flush() error  // fsync fd (flushes MAP_SHARED pages on Linux)
func (i *offsetIndex) rename(newPath string) error; close() error
// time index: 12-byte entries (timestamp int64, relOffset uint32); same API shape plus
func (t *timeIndex) maybeAppend(ts int64, offset int64, force bool) error // only if ts > last ts
func (t *timeIndex) lookup(ts int64) (tsFound int64, offset int64)        // largest entry ts <= target
func (t *timeIndex) lastEntry() (int64, int64)
```
- Opened files are extended (sparse `ftruncate`) to `maxBytes` and mapped `MAP_SHARED`. On open,
  the valid entry count is the length of the leading run of strictly increasing entries (a zeroed
  preallocated tail ends the run; entry `(0,0)` is never written because the first entry is only
  added after `IndexIntervalBytes`). A trimmed file's size is exactly `n*entrySize`.
- Concurrency: the single writer appends under the log's mutex. Entry count is an `atomic.Int64`
  stored **after** the entry bytes are written; readers binary-search only `[0, count)`. A per-index
  `sync.RWMutex` is held (read) by lookups and taken (write) only by `close`/`truncateTo`/`reset`,
  so a reader can never touch an unmapped region (a lookup after close returns `(base,0)`).
- `trim()` on roll shrinks the file but keeps the mapping (pages past EOF are never accessed),
  so concurrent readers stay safe.

### 2.3 Checkpoints (`checkpoint.go`)
Kafka-compatible text format: line 1 version `0`, line 2 entry count, then entries.
```go
func WriteOffsetCheckpoint(ctx, path string, offsets map[TopicPartition]int64) error // "topic partition offset"
func ReadOffsetCheckpoint(ctx, path string) (map[TopicPartition]int64, error) // missing -> empty
func WriteLeaderEpochCheckpoint(ctx, path string, entries []EpochEntry) error   // "epoch startOffset"
func ReadLeaderEpochCheckpoint(ctx, path string) ([]EpochEntry, error)
type EpochEntry struct { Epoch int32; StartOffset int64 }
```
Atomic write: write `path.tmp`, fsync, rename over `path`, fsync the directory. Read rejects wrong
version, count mismatch, malformed lines (`ErrCorruptCheckpoint`); a stray `.tmp` is ignored.
Entries are written sorted (deterministic files). Used by: `Manager` for
`recovery-point-offset-checkpoint`; `replication-offset-checkpoint` (HW) is written by the broker
from M2 via the same helper; leader-epoch-checkpoint by `internal/partition` in M6.

### 2.4 Segment (`segment.go`)
```go
type segment struct {
    baseOffset int64; log *os.File; index *offsetIndex; timeIndex *timeIndex
    size atomic.Int64          // published byte size; readers never read past it
    nextOffset atomic.Int64    // offset after the last batch
    maxTimestamp atomic.Int64; rollingBaseTs int64 /* first batch's maxTimestamp, or open time */
    bytesSinceIndex int; dir string; cfg LogConfig
}
func createSegment(dir string, base int64, cfg LogConfig, now time.Time) (*segment, error)
func openSegment(dir string, base int64, cfg LogConfig, now time.Time) (*segment, error)
func (s *segment) append(b record.Batch) error // WriteAt(size); on short write/err ftruncate back
    // to old size; index entry if bytesSinceIndex >= interval; timeindex maybeAppend; then
    // publish size, nextOffset (atomic stores, in that order)
func (s *segment) read(startOffset int64, maxBytes int, maxOffset int64, firstBatchMustFit bool) ([]byte, error)
    // index lookup -> scan headers with ReadAt up to published size -> first batch whose
    // lastOffset >= startOffset; then whole batches while baseOffset < maxOffset and fit maxBytes
    // (the first batch is always returned whole unless firstBatchMustFit)
func (s *segment) findOffsetByTimestamp(ts int64) (int64, bool, error)
func (s *segment) recover() (truncated bool, err error)
    // reset both indexes, scan from 0: ParseHeader, bounds, Validate (CRC), baseOffset ==
    // expected; rebuild indexes; on first bad/partial batch ftruncate .log there
func (s *segment) loadState() error // non-recovered segment: sanity-check indexes (rebuild via
    // recover() if bad), compute nextOffset by scanning from the last index entry
func (s *segment) onRoll() error    // force final timeindex entry (max ts), trim + fsync indexes, fsync log
func (s *segment) flush() error; close() error
func (s *segment) renameForDelete() error // append ".deleted" to all three files
func (s *segment) deleteFiles() error     // close + unlink (the ".deleted" names)
```
File names: `fmt.Sprintf("%020d", base)` + `.log`/`.index`/`.timeindex`.

### 2.5 Log (`log.go`, `recovery.go`)
```go
type Log struct {
    mu sync.Mutex                         // single writer: append, roll, flush capture, retention, close
    segments atomic.Pointer[[]*segment]   // immutable, copy-on-write; readers load lock-free
    logStartOffset atomic.Int64; leo atomic.Int64; recoveryPoint atomic.Int64
    lastFlush time.Time; tp TopicPartition; dir string; cfg LogConfig; clock Clock; logger *slog.Logger
    onDelete func(*segment)               // hands renamed segments to the Manager
}
type AppendInfo struct { FirstOffset, LastOffset, MaxTimestamp int64 }
type ReadResult struct { Data []byte; LogStartOffset, LogEndOffset int64 } // Data = whole batches

func OpenLog(ctx, dir string, tp TopicPartition, cfg LogConfig, recoveryPoint int64,
    clock Clock, logger *slog.Logger, onDelete func(*segment)) (*Log, error)
func (l *Log) Append(ctx, b record.Batch, leaderEpoch int32) (AppendInfo, error)
    // record.Validate(b, MaxMessageBytes) (ErrMessageTooLarge / ErrCorruptBatch); stamp
    // baseOffset=LEO and leaderEpoch in place; maybeRoll; segment.append; leo.Store;
    // FlushPolicy=always -> fsync + recoveryPoint before returning
func (l *Log) Read(ctx, startOffset int64, maxBytes int, maxOffset int64) (ReadResult, error)
    // lock-free. startOffset < logStart or > LEO -> ErrOffsetOutOfRange; startOffset >=
    // maxOffset -> empty. maxOffset is the caller's bound: HW for consumers, LEO for replicas.
func (l *Log) OffsetForTimestamp(ctx, ts int64) (offset int64, found bool, err error)
    // earliest offset whose record timestamp >= ts (first segment with maxTimestamp >= ts,
    // timeindex lookup, scan batches, then records inside the first matching batch)
func (l *Log) Flush(ctx) error       // capture LEO + segments under mu, fsync outside mu, then
    // recoveryPoint = max(recoveryPoint, captured LEO)
func (l *Log) MaybeFlush(ctx, now time.Time) error // interval policy: Flush if dirty and FlushMs elapsed
func (l *Log) DeleteOldSegments(ctx, now time.Time, limitOffset int64) (int, error)
    // non-active segments only, and only those with nextOffset <= limitOffset (HW from M2);
    // time: maxTimestamp < now-RetentionMs; size: oldest first while total-seg.size >= RetentionBytes.
    // §3.3: publish new slice without them, bump logStartOffset, renameForDelete, onDelete(seg)
func (l *Log) LogStartOffset() int64; LogEndOffset() int64; RecoveryPoint() int64; Size() int64
func (l *Log) Close() error          // flush (all policies), trim indexes, close files
```
Roll (`maybeRoll`, under `mu`): when `active.size + len(b) > SegmentBytes`, or the active segment
is non-empty and `now - rollingBaseTs > SegmentMs`, or either index `isFull()`: `onRoll()` the
active segment, `createSegment(LEO)`, fsync the directory, publish the new slice.
A batch larger than `SegmentBytes` is impossible (`MaxMessageBytes <= SegmentBytes`, validated).

Recovery (`OpenLog`, §3.4): delete leftover `*.deleted` files and index files without a `.log`;
open segments in base-offset order (create one at offset 0 if none); segments wholly below the
recovery point use `loadState()`; the segment containing the recovery point and all later ones use
`recover()`. If a segment is truncated, every later segment is deleted. LEO = last segment's
nextOffset; logStartOffset = first segment base. A truncation is logged at WARN with
topic/partition/offset.

Lock ordering (documented in `doc.go`): `Manager.mu` → `Log.mu` → `index.mu`. Readers take only
`index.mu` (read). `Flush` releases `Log.mu` before fsync.

### 2.6 Manager (`manager.go`)
```go
type ManagerConfig struct { DataDir string; FileDeleteDelay time.Duration;
    FlushCheckInterval, RetentionCheckInterval, CheckpointInterval time.Duration } // 100ms/5m/5s
func OpenManager(ctx, cfg ManagerConfig, clock Clock, logger *slog.Logger) (*Manager, error)
    // mkdir, read recovery-point-offset-checkpoint, delete leftover *.deleted in all partition dirs
func (m *Manager) GetOrCreateLog(ctx, tp TopicPartition, cfg LogConfig) (*Log, error)
func (m *Manager) Log(tp TopicPartition) (*Log, bool)
func (m *Manager) Run(ctx) error  // one goroutine, tickers; returns nil on ctx cancel
func (m *Manager) FlushDirty(ctx, now) error; RunRetention(ctx, now, limit func(TopicPartition) int64) error
func (m *Manager) CheckpointRecoveryPoints(ctx) error; DeleteExpired(ctx, now) error // one pass each
func (m *Manager) Close(ctx) error // close all logs (flush), write recovery checkpoint, unlink pending
```
`Run` calls the one-pass methods; tests call them directly with a fake clock, so no test depends on
real timers. Pending deletions are `{seg, dueAt = now + FileDeleteDelay}`; `DeleteExpired` closes and
unlinks those that are due. `Close` unlinks all pending (their `.deleted` names would be removed at
next startup anyway).

## 3. Tests (`internal/storage`, all with `goleak.VerifyTestMain`, `t.TempDir()`, fake clock)

- **Indexes**: append/lookup table (before first entry, exact, between, after last); truncateTo;
  ErrIndexFull; reopen after trim and after an untrimmed crash (zeroed tail) recovers the count;
  sanityCheck rejects decreasing entries and positions ≥ log size; lookup after close is safe.
- **Checkpoints**: round trip (incl. topic names containing `-`), missing file → empty, bad
  version/count/line → `ErrCorruptCheckpoint`, stray `.tmp` ignored.
- **Append/read**: offsets contiguous across batches; read from offset inside a batch returns that
  batch; maxBytes returns the first batch whole even if larger, then only whole batches; maxOffset
  bound stops below it; startOffset == LEO → empty; > LEO and < logStart → `ErrOffsetOutOfRange`;
  too-large and corrupt batches rejected with nothing written.
- **Roll**: by size (file names 20-digit, contiguous offsets across segments, reads span
  segments), by time (fake clock), by full index; reopen after clean close → identical reads.
- **Retention**: by time, by size, never the active segment, never past `limitOffset`;
  logStartOffset advances; files renamed `.deleted`, still present until `DeleteExpired` after the
  delay, then gone; a reader holding the old segment can read it after removal from the list;
  startup removes leftover `.deleted` files.
- **Recovery** (§9): (a) truncate the last `.log` mid-batch → reopen → LEO = end of last complete
  batch, reads of everything before succeed, next append gets that offset; (b) corrupt one CRC byte
  in a batch of the middle segment of three → log truncated before that batch, the third segment
  deleted, indexes rebuilt (lookup of every surviving offset works); (c) garbage index file for a
  segment below the recovery point → rebuilt; (d) recovery-point checkpoint round trip through
  `Manager` (clean close → LEO checkpointed).
- **Flush policy**: always → recoveryPoint == LEO after each append; interval → only after
  `MaybeFlush` past `FlushMs`; never → only on Close.
- **OffsetForTimestamp**: table over batches with out-of-order timestamps; ts beyond max → not found.
- **Concurrency (`-race`)**: 1 writer appending with tiny segments (forcing many rolls) +
  retention deleting old segments + 4 readers continuously reading from random valid offsets and
  verifying every decoded record's value encodes its own offset and offsets are contiguous. Runs a
  fixed number of iterations; synchronized by WaitGroup, no sleeps.
- **Manager**: GetOrCreateLog idempotent; Run exits on cancel (goleak); FlushDirty / RunRetention /
  DeleteExpired one-pass behaviour; LogConfig.Validate table (segment.bytes > 1 GiB rejected).
- **Benchmarks**: `BenchmarkAppend` (1 KiB records × {1, 100} per batch, policy never and
  interval), `BenchmarkRead`. Report MB/s via `b.SetBytes`.

Makefile: `fuzz` → `go test ./internal/record -run='^$$' -fuzz=FuzzValidate -fuzztime=30s`;
`bench` → `go test -run='^$$' -bench=. -benchmem ./internal/storage/...` (bench/ tool comes in M10).

## 5. Decisions (to record in DECISIONS.md)
- D3 Index files: big-endian entries, preallocated to `MaxIndexBytes` (10 MiB), count recovered as
  the leading strictly-increasing run; indexes of segments at/after the recovery point are always
  rebuilt (they are never trusted after a crash).
- D4 Time-based roll uses Kafka's formula (see R4): incoming batch maxTimestamp minus the segment's
  first batch maxTimestamp, or wall clock minus segment creation when that is unknown; retention by
  time uses segment maxTimestamp.
- D5 Recovery requires contiguous offsets inside the log (batch baseOffset == previous nextOffset);
  a gap is treated as corruption and truncates.
- D6 Storage APIs that do I/O take `ctx` and check `ctx.Err()` before starting; file I/O itself is
  not interruptible.
- D7 Deleted segments are closed and unlinked after `file.delete.delay.ms` (no reader refcount); a
  reader still holding one after the delay gets an `os.ErrClosed`-wrapped error, never a crash
  (index lookups hold the index RWMutex).

## Revision 1 (after plan-review round 1)

These rules supersede anything above that conflicts with them.

- **R1 (finding 1)** `LogConfig.Validate` only requires `MaxIndexBytes >= 24`. Each index rounds
  `maxBytes` down to a multiple of its entry size (8 or 12). Test: `DefaultLogConfig().Validate()`
  returns nil.
- **R2 (finding 2)** `segment.recover()` never applies `MaxMessageBytes`. A batch is bounded only
  by the bytes left in the file (and `MaxSegmentBytes`). `MaxMessageBytes` is enforced only on
  `Append`. Test: append a 900 KiB batch, close, reopen with `MaxMessageBytes` = 1 KiB and
  recoveryPoint 0. Nothing is truncated.
- **R3 (finding 3) Publication order**:
  - Retention stores the new `logStartOffset` *before* publishing the shortened slice.
  - Roll publishes the new slice *before* the append stores the new LEO.
  - `Read` loads `logStartOffset`, then LEO, then the slice. If no segment in the slice covers
    `startOffset` (it is below `segs[0].base`), it returns `ErrOffsetOutOfRange`. It never indexes
    out of range.

  Deletion (time and size) walks oldest-first and stops at the first segment that does not qualify,
  so only a contiguous prefix is ever removed (Kafka `deleteOldSegments`). Test: segment 1 is not
  expired and segment 2 is. Both are kept.
- **R4 (finding 4) Time roll (Kafka `timeWaitedForRoll`)**: roll when the active segment is
  non-empty and `waited > SegmentMs`, where `waited = incomingBatch.MaxTimestamp - rollingBaseTs`
  if the segment has a rolling base timestamp (the first batch's maxTimestamp), else
  `now - createdAt`. Test: 1000 batches with timestamp 0 produce no roll. A batch whose timestamp is
  `SegmentMs+1` past the first one rolls. An empty segment never rolls.
- **R5 (finding 5) Time index semantics (frozen)**: an entry is (largest batch maxTimestamp seen
  so far in the segment, **baseOffset of the batch where that maximum was first seen**).
  `OffsetForTimestamp` asks the time index for the largest entry with timestamp **strictly less
  than** the target (`lookup(ts-1)`), maps its offset through the offset index to a position, scans
  batches forward to the first with `maxTimestamp >= ts`, then returns the first record in it with
  `timestamp >= ts`. Test: `IndexIntervalBytes = 1`, several batches sharing the target timestamp
  across entries, and out-of-order timestamps. The earliest matching offset is returned.
- **R6 (finding 6) Canonical batches**: `Validate` accepts only canonical batches, so a
  decode → rebuild round trip is exact:
  - varints must be minimal-length (re-encoded length must equal consumed length);
  - batch attributes == 0 and record attributes == 0;
  - first record `timestampDelta == 0`, and header `maxTimestamp` == max over records;
  - `offsetDelta` == index, `lastOffsetDelta == recordCount-1`, and each record's `length` matches
    its encoded body exactly;
  - header keys must not be null (length >= 0); header values may be null;
  - `headerCount >= 0`; no trailing bytes.

  `Builder` produces exactly this form. `Records()` returns `Key`/`Value`/header values that
  **alias** the batch buffer (documented). Null vs empty is preserved (nil vs non-nil empty).
  The fuzz property: if `Validate` succeeds, rebuilding from `Records()` with the batch's producer
  fields gives identical CRC-covered bytes.
- **R7 (finding 7) Split**:
  - The **contract commit** includes `go.mod`/`go.sum` with testify + goleak,
    `internal/record/main_test.go` and `internal/storage/main_test.go` (goleak `VerifyTestMain`),
    and `internal/storage/testutil_test.go` (`fakeClock` with `Now`/`Advance`, plus
    `buildBatch(t, ts, values...)`). Implementers must not define `TestMain`, `fakeClock` or
    `buildBatch` themselves.
  - Done criteria: A runs `go test -race ./internal/record/...` and
    `golangci-lint run ./internal/record/...`. B runs `go test -race -run 'Index|Checkpoint|Mmap'
    ./internal/storage/` and checks that lint shows no issues in B's own files (unused-stub
    warnings in files B doesn't own are expected until integration).
  - A and B are merged **before** C is committed. C's tests and full `make lint test` run on the
    merged tree before the C commit. While A and B run, the main session writes C against the
    contract.
- **R8 (finding 8)** Recovery test (b) reopens with recoveryPoint = 0 (no checkpoint, which
  simulates an unclean shutdown). `OpenLog` clamps a recovery point above LEO down to LEO.
  Also, the last segment is always recovered, plus every segment whose successor's base offset is
  > recoveryPoint. After recovery the recovered segments are fsynced and recoveryPoint = LEO.
- **R9 (finding 9) Index entries (frozen, D3)**:
  - Before writing a batch at position `pos`, if `bytesSinceIndex >= IndexIntervalBytes`, add
    offset-index entry (batch **baseOffset**, `pos`) and a time-index entry, then reset the
