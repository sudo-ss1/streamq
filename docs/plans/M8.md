## 1. Metrics contract (`internal/metrics`)

One `Metrics` struct per node. It owns its own `prometheus.Registry`: no globals and no default
registry, as CLAUDE.md requires. The dependency `github.com/prometheus/client_golang` is on the
approved list.

```go
type Metrics struct { /* registry + vecs */ }
func New() *Metrics                                   // registers Go and process collectors too
func (m *Metrics) Registry() *prometheus.Registry
func (m *Metrics) Handler() http.Handler              // promhttp.HandlerFor(registry, ...)
func (m *Metrics) UnaryServerInterceptor(service string) grpc.UnaryServerInterceptor
func (m *Metrics) AddBytesIn(topic string, n int)     // nil-safe receiver
func (m *Metrics) AddBytesOut(topic string, n int)
func (m *Metrics) RegisterBroker(src BrokerSource)    // pull collector, scrape-time
func (m *Metrics) RegisterRaft(src RaftSource)

type PartitionStat struct { Topic string; Partition int32; Leader bool; LEO, HW int64; ISRSize, Replicas int }
type LagStat struct { Group, Topic string; Partition int32; Lag int64 }
type BrokerSource interface {
	PartitionStats() []PartitionStat   // every local replica
	ConsumerLag() []LagStat            // for partitions this broker leads: HW - committed (>= 0)
	OfflinePartitions() (int, bool)    // count, and whether this broker reports it (the controller, or single-node)
}
type RaftStats struct { State string; LastContact time.Duration; Term, CommitIndex, AppliedIndex uint64 }
type RaftSource interface { RaftStats() RaftStats }
```

**Metric names** (B's Grafana dashboard uses exactly these):
- `streamq_requests_total{service,method,code}`: counter; `code` is the gRPC status code.
- `streamq_request_duration_seconds{service,method}`: histogram, buckets 0.5 ms–10 s.
- `streamq_bytes_in_total{topic}`: record bytes in Produce requests.
- `streamq_bytes_out_total{topic}`: record bytes in Fetch responses.
- `streamq_partition_log_end_offset{topic,partition}` and
  `streamq_partition_high_watermark{topic,partition}`: gauges for every local replica.
- `streamq_partition_isr_size{topic,partition}` and `streamq_partition_replicas{topic,partition}`:
  reported by the leader only.
- `streamq_partitions_leader`: the number of partitions this broker leads.
- `streamq_partitions_under_replicated`: led partitions with ISR < replicas.
- `streamq_partitions_offline`: reported by the controller only; the other brokers do not export
  it, so a sum is correct.
- `streamq_consumer_lag{group,topic,partition}`.
- `streamq_raft_state{state}`: 1 for the current state, 0 for the others (leader, follower,
  candidate, shutdown).
- `streamq_raft_last_contact_seconds`, `streamq_raft_term`, `streamq_raft_commit_index` and
  `streamq_raft_applied_index`: cluster mode only.

**Where the data comes from**
- `broker.Broker` implements `BrokerSource` in `stats.go`:
  - from its partitions map: LEO, HW, leader flag, ISR size, replicas;
  - lag: the metadata snapshot's committed group offsets, for led partitions only;
  - offline count: metadata partitions with leader −1, reported when the snapshot's controller is
    this broker.
  - Each partition gains a read-only accessor `ISRSize() int` (committed ISR) and
    `ReplicaCount() int`. These are additive, in the contract.
- `raftstore.Store` implements `RaftSource` in `stats.go`, from `raft.Stats()` and
  `raft.LastContact()`.

**Wiring (contract, main session)**
- `node` builds `metrics.New()` and registers the broker (and raft in cluster mode).
- It installs `UnaryServerInterceptor("client")` on the public gRPC server and
  `UnaryServerInterceptor("internal")` on the internal one.
- It serves `/metrics` on `metrics_addr` (empty disables) through its own `http.Server`.
  `Options.Metrics net.Listener` exists for tests. The server shuts down in `Close` after the
  gRPC servers.
- The `Server` gets a `*metrics.Metrics`, nil-safe, as a new constructor argument. `Produce` and
  `Fetch` call `AddBytesIn` and `AddBytesOut`.

**Logs (NFR7)**
- Existing `slog` fields already carry `broker_id`, `topic` and `partition`.
- M8 adds request-error logs at debug level in the interceptor, and logs the shutdown phases at
  info level.

## 2. Package B details
- **`Dockerfile`** (multi-stage):
  - built with `golang:1.26` (or the `go.mod` version) using `CGO_ENABLED=0`;
  - runs on `gcr.io/distroless/static` with both binaries.
- **`deploy/docker-compose.yml`:**
  - `broker1..3`: configs in `deploy/brokerN.yaml`, data in named volumes.
  - `toxiproxy`, with `deploy/toxiproxy.json` defining one proxy per broker per internal/raft port.
    The brokers' `cluster:` addresses point at the proxies, so M9 can inject faults on
    broker-to-broker traffic. Client ports are published directly.
  - `prometheus`, with `deploy/prometheus.yml` scraping `brokerN:9100`.
  - `grafana`, with provisioning in `deploy/grafana/provisioning/{datasources,dashboards}` and the
    dashboard JSON in `deploy/grafana/dashboards/streamq.json`. Panels: request rate and p99 per
    method, bytes in/out, under-replicated and offline partitions, ISR size, LEO/HW per partition,
    consumer lag, Raft state and last contact.
  - The advertised host per broker is `localhost`, with distinct published client ports
    (9092/9192/9292), so `streamqctl` works from the host.
- **Makefile:**
  - `cluster-up` runs `docker compose -f deploy/docker-compose.yml up -d --build`;
  - `cluster-down` runs `docker compose -f deploy/docker-compose.yml down -v`.
- **`streamqctl cluster status`:**
  - Calls `Metadata` (all topics) through the bootstrap.
  - Prints the controller id, then a broker table: id, address, live, and whether it is the
    controller. A broker referenced as a replica but missing from the live list is shown as down.
  - Then partition health per topic: partitions, under-replicated (ISR < replicas), offline
    (leader −1).
  - Exits non-zero (`--strict`) when anything is under-replicated or offline.
  - Output goes through `cmd.OutOrStdout()`. A test runs it against a 3-node in-process cluster,
    with one broker stopped.

## 3. Controlled shutdown (§4.6) and graceful shutdown (NFR4): main session
- **Proto (internal, additive):** `rpc ControlledShutdown(ControlledShutdownRequest{broker_id,
  broker_epoch}) returns (ControlledShutdownResponse{error_code, error_message, controller_id})`.
- **`controller.ControlledShutdown(ctx, id, epoch)`:**
  - checks the active term and the broker epoch (`ErrStaleBrokerEpoch`);
  - marks `brokerState.shuttingDown`, so a racing `Heartbeat` never unfences it; a new epoch
    (re-registration) resets the flag;
  - applies a term-stamped `FenceBroker{id, epoch}`. The FSM's existing fence logic elects new
    leaders from the remaining ISR and removes the broker from the ISR (D34; the last ISR member
    keeps its place).
  - It is idempotent: an already-fenced broker gets success.
- **`Node.Close` order in cluster mode**, before the existing steps:
  1. Stop the liveness loop. It gets its own cancel, so the internal server and controller keep
     running.
  2. Call `ControlledShutdown` on the controller, retrying with backoff until success or
     `ControlledShutdownTimeout`. That is `controlled_shutdown_timeout_ms`, a new config key
     defaulting to 30000, validated > 0, and also added to SPEC §10 in DECISIONS.
  3. Wait, bounded by the same timeout, until local metadata shows no partition led by this
     broker.
  4. If this node is the Raft leader, call `raft.LeadershipTransfer()` (best effort, bounded) so
     the controller moves before the server goes away.
  5. Continue with the existing graceful steps:
     - `BeginShutdown`, then `GracefulStop` of the client server (bounded);
     - close the coordinator;
     - close the broker: stop fetchers, flush logs, producer snapshots, then the HW and
       recovery-point checkpoints;
     - stop the background loops and the internal server;
     - close the store.

  Failures in steps 2–4 are logged and never block shutdown beyond the timeout.
- **Single-node mode:** only step 5.
- **Tests (`test/integration/shutdown_test.go`):**
  1. **Controlled shutdown.** A 3-node cluster with `broker_session_timeout_ms` set to 10 s, so
     fencing by liveness cannot explain the result. Create a topic with 6 partitions at RF 3.
     Gracefully stop the broker that leads the most partitions. Within 1 s of `Stop` returning,
     well below the session timeout, every partition has a leader ≠ the stopped broker with a
     bumped epoch, and acks=all produce to every partition succeeds. After a restart, the broker
     rejoins the ISR.
  2. **Controller self-shutdown.** Stopping the controller broker moves both partition leadership
     and the Raft leadership. A new controller id appears within 2 s.
  3. **SIGTERM graceful (NFR4)** with the `kill_test.go` process harness:
     - produce, then send SIGTERM;
     - the process exits with code 0 within 30 s;
     - the recovery-point checkpoint equals the LEO for every partition, the HW checkpoint
       exists, and each partition has a producer snapshot at its LEO;
     - after a restart all records are readable.
  4. **Controller unit tests:** controlled shutdown fences the broker and elects new leaders, is
     idempotent, rejects a stale epoch, and a heartbeat after it does not unfence.
